Self-hosted observability without a database cluster to run

NebuLens stores traces, logs and metrics in SQLite or Postgres. The popular open-source stacks are built on ClickHouse or on four separate backends. Here is what that means for you, and when they are the better choice.

Why teams pick NebuLens

Nothing new to operate

Postgres is a database your team already knows how to back up, size, encrypt and get through an audit. There is no ClickHouse, Kafka or ZooKeeper to learn. Give NebuLens its own Postgres database or instance, not your application's production one.

Up in about 20 minutes

One Helm chart deploys the server, the collector and eBPF tracing. Existing OpenTelemetry apps only change their exporter endpoint.

No privileged agent by default

The default install is the standard OpenTelemetry Collector and one server, with no privileged agent on your nodes. eBPF tracing is a switch you turn on only if you want it. Licences are checked offline, so it runs air-gapped.

When another tool is the better choice

We would rather you pick the right tool than switch twice.

  • You ingest far more than a few thousand spans per second. ClickHouse-based tools such as Coroot, SigNoz and ClickStack scale further on one installation.
  • You want the deepest eBPF view at the lowest price and can run ClickHouse. Coroot is free with no node limit and $1 per CPU core with SSO and RBAC.
  • You are log-heavy and under 50 GB a day. OpenObserve's self-hosted Enterprise edition is free at that size and includes SSO and an audit trail.
  • You need a vendor with a SOC 2 Type II report or a signed BAA today. NebuLens runs entirely inside your network and never receives your data, but it does not yet hold those certifications.
  • You want a hosted service. SigNoz Cloud, ClickHouse Cloud and Grafana Cloud run it for you; NebuLens is self-hosted only.
  • You already run the Grafana stack well. Keep it; the cost of switching is real.

Try it next to what you have

Because every tool here speaks OpenTelemetry, you can send the same data to both and compare for two weeks. Add a second exporter to your existing collector:

exporters:
  otlphttp/nebulens:
    endpoint: http://nebulens.observability:4318
service:
  pipelines:
    traces:
      exporters: [otlphttp/current, otlphttp/nebulens]
