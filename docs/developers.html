Observability you can install before your coffee cools.

NebuLens is a self-hosted OpenTelemetry backend with a UI that's actually nice to use. One container, one port, one environment variable in your app. Traces, logs and metrics show up seconds later.

# the whole integration, for any OpenTelemetry SDKOTEL_EXPORTER_OTLP_ENDPOINT=http://nebulens:4318
$ installview source
// step 1

Install it where you already run things.

Kubernetes with Helm, a single VM with Docker Compose, or your laptop. Same server, same UI.

# build and push the image to your registry
docker build -t registry.example.com/nebulens:11.1 . && docker push registry.example.com/nebulens:11.1

# install the server, collectors and Kubernetes metrics in one release
helm install nebulens ./helm/nebulens -n observability --create-namespace \
  --set image.repository=registry.example.com/nebulens --set-string image.tag=11.1 \
  --set auth.token=$(openssl rand -hex 24)
# on any Linux VM with Docker
cd deploy/vm
cp .env.example .env            # set NEBULENS_TOKEN and NEBULENS_IMAGE
docker compose up -d

# UI and OTLP endpoint
open http://your-vm:4318
pip install -r requirements.lock
python server.py                # http://localhost:4318

# send some demo traffic from 23 services
NEBULENS_URL=http://localhost:4318 python demo/multi_service_load.py

Check it end to end: python scripts/smoke.py http://<host>:4318 --token <token>

// step 2

Point your services at it.

NebuLens speaks plain OTLP over HTTP, so any OpenTelemetry SDK or collector works. No proprietary agent, no lock-in.

pip install opentelemetry-distro opentelemetry-exporter-otlp
opentelemetry-bootstrap -a install

OTEL_SERVICE_NAME=checkout \
OTEL_EXPORTER_OTLP_ENDPOINT=http://nebulens:4318 \
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf \
opentelemetry-instrument python app.py
npm install @opentelemetry/auto-instrumentations-node

OTEL_SERVICE_NAME=cart \
OTEL_EXPORTER_OTLP_ENDPOINT=http://nebulens:4318 \
node --require @opentelemetry/auto-instrumentations-node/register app.js
# download opentelemetry-javaagent.jar from the OpenTelemetry releases page
OTEL_SERVICE_NAME=orders \
OTEL_EXPORTER_OTLP_ENDPOINT=http://nebulens:4318 \
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf \
java -javaagent:opentelemetry-javaagent.jar -jar orders.jar
// go get go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracehttp
exp, _ := otlptracehttp.New(ctx)   // reads OTEL_EXPORTER_OTLP_ENDPOINT
tp := sdktrace.NewTracerProvider(sdktrace.WithBatcher(exp))
otel.SetTracerProvider(tp)

// run with
OTEL_SERVICE_NAME=pricing OTEL_EXPORTER_OTLP_ENDPOINT=http://nebulens:4318 ./pricing
# install the OpenTelemetry Operator together with NebuLens (skip if your cluster already has one)
helm upgrade nebulens ./helm/nebulens -n observability --reuse-values \
  --set opentelemetry-operator.enabled=true --wait --timeout 5m

# switch tracing on for a workload: the pod restarts with the language agent injected
scripts/instrument.sh python -n shop checkout     # java, dotnet, nodejs, go

# or let NebuLens annotate whole namespaces every 10 minutes (it detects the language)
helm upgrade nebulens ./helm/nebulens -n observability --reuse-values \
  --set autoInstrumentation.autoInject.enabled=true --set autoInstrumentation.autoInject.dryRun=false \
  --set "autoInstrumentation.autoInject.namespaces={shop}"

RED for every service

Rate, errors and p50/p95/p99 latency with a health score, pre-computed every minute so pages stay fast at millions of spans.

Kubernetes built in

The chart ships collectors for host, kubelet and cluster metrics plus container logs. Pods, nodes and workloads appear without extra setup.

Your database

SQLite on local disk for one node, or point NEBULENS_DATABASE_URL at your own Postgres.

// step 4 (optional)

Everything in the UI is an API call.

Script dashboards, alerts and checks, or pull data into your own tools. Same token, plain JSON.

# services with RED metrics for the last hour
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://nebulens:4318/api/services?minutes=60"

# the slowest traces for one service
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://nebulens:4318/api/traces?service=checkout"
# ask the assistant from a script or a bot
curl -s -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"why is checkout slow?"}]}' \
  http://nebulens:4318/api/assistant
